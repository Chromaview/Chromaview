# Writing & Maintaining Documentation

## Philosophy

- Prefer concise, example-driven documentation.
- Keep examples runnable and tested when possible.
- Update docs alongside code changes in the same commit.

## How to Add an API Entry

1. Update `docs/API.md` module section.
2. Add or update examples in `docs/examples/` if applicable.
3. Link to related components or backend sections.

## Style

- Use sentence case for headings.
- Use backticks for code identifiers and file paths.
- Include Types/Shapes for inputs and outputs when known.

## Verification Checklist

- Have you included a usage example?
- Are parameters and return types described?
- Are breaking changes noted with migration guidance?
